This is another important part.

Model parameters normally use numerical formats such as:

FP32 → 32-bit
FP16 → 16-bit
INT8 → 8-bit
INT4 → 4-bit

INT4 uses much less memory than FP16/FP32.

That's particularly useful on your PC because you have 16 GB RAM and we're running the model locally on CPU.

So today's setup was essentially:

Gemma 2B Instruction-Tuned → converted to ONNX → quantized to INT4 → executed locally through ONNX Runtime GenAI from C#.

**************Transformer***************

A Transformer is a type of neural network architecture designed to understand relationships between 
words/tokens in a sequence. It is the architecture behind models 
such as Gemma, GPT, BERT, and many other modern LLMs.

In this context, “sequence” simply means an ordered list of tokens.

For example, take this sentence:

"I love C# programming"

After tokenization, it might become something like:

["I", "love", "C#", "programming"]

This is a sequence because the tokens have a specific order:

1 → I
2 → love
3 → C#
4 → programming
Why does order matter?

Compare:

"I love C#"

with:

"C# love I"

They contain similar words, but the order is different, so the meaning is different.

That's why a Transformer needs to understand the relationship between tokens within a sequence.

In ML/LLM terminology

You can think of it like this:

Sentence
   ↓
Tokenizer
   ↓
Token IDs
   ↓
[101, 2057, 2293, 1046, ...]
   ↑
   └── This ordered collection is a sequence

So when I said:

“Transformers understand relationships between words/tokens in a sequence.”

I simply meant:

Transformers understand how tokens relate to each other while considering their order in the input.

For example:

"The cat eats fish"

Sequence:
[The] → [cat] → [eats] → [fish]

And self-attention helps each token look at the other tokens in that sequence and determine which ones are important.

⭐ Complete generation flow

You now know almost the entire generation process:
                 USER PROMPT
                      ↓
                  Tokenizer
                      ↓
                  Token IDs
                      ↓
                 Embeddings => Token ID → vector used internally by the LLM.
                      ↓
                 Transformer => Neural Network Architecture or Behind the Architecture of LLMs model
                      ↓
                Self-Attention  => Self-attention mainly allows tokens to exchange information.
                                   Attention helps the model understand relationships between words.
                      ↓
                    FFN => Feed-Forward Network (also called Feed-Forward Neural Network)
                            Then FFN takes the resulting representation and performs 
                            additional nonlinear transformations on it.

                            FFN processes the vector representation of each token, using information that 
                            the token representation has received from self-attention.

                            Important: FFN does not directly produce words or the final answer. 
                            It produces transformed vectors that help the model eventually predict the next token.
                      
                            The key idea: Self-Attention helps a token use information from other tokens; 
                            FFN processes the representation it has received. 
                            Together, they help Gemma understand context and generate its response.
                      ↓
                  Logits => raw scores for each possible next token. the model produce it
                      ↓
                 Temperature => controls the randomness/variability of token selection.
                                The key is that temperature changes the probability distribution, not the model's learned knowledge.
                                    - Low temperature: more predictable output.
                                    - High temperature: more varied output.
                                    - Temperature = 1: leaves logits unchanged before Softmax.
                      ↓
                  Softmax => Softmax converts logits (raw scores) into probabilities.
                      ↓
              Probability Distribution => A probability distribution shows how likely each possible next token is.
                                        A probability assigned to every possible next token
                      ↓
              Top-K / Top-P =>, K = 3 → keep only the top 3 tokens.
                                Top-P → Keep the smallest group of tokens whose cumulative probability reaches P.
                      ↓
                  Sampling => choosing the next token from the remaining probability distribution.
                      ↓
                Next Token
                      ↓
              Add to context => include previous information in the model's current input 
                                so it can use that information when generating the next response.
                      ↓
                 Transformer
                      ↓
                  Next Token
                      ↓
                    ...
                      ↓
                  EOS(End Of Sequence) / Stop => The response is finished. Stop generating
                      ↓
                 Decode Tokens => convert token IDs back into human-readable text.
                      ↓
                  Final Answer

🧠 Remember these four

This is the important part to memorize:

| Concept         | Simple meaning                                 |
| --------------- | ---------------------------------------------- |
| **Logits**      | Raw scores for possible next tokens            |
| **Temperature** | Controls randomness                            |
| **Top-K**       | Keep the best K candidates                     |
| **Top-P**       | Keep candidates covering probability P         |
| **Sampling**    | Choose one token from the remaining candidates |

Lesson 1: Context Window
1. What is a Context Window?

A context window is the maximum number of tokens a model can process as its current context.

Think of it as the model's working space. It can include the current question, previous conversation messages, 
        and other supplied information.

For example, 
    suppose a model has a context window of 4,096 tokens.
Context Window
4,096 tokens = Question + History + Answer


Illustration only: the context is shared by the prompt and generated tokens, subject to the model's and runtime's limits.

The 4,096-token limit here is an example, not a statement that every Gemma configuration has that exact limit.

2. What counts as a token?
Tokens are pieces of text, not necessarily whole words.
For example:
Input:
"What is C#?"

Possible tokenization:
["What", " is", " C", "#", "?"]

This is illustrative; the actual tokenization depends on the tokenizer.
The model counts tokens, not simply words or characters.

 ***What happens when the context becomes too large?
Imagine a conversation keeps growing:
Question 1
    ↓
Answer 1
    ↓
Question 2
    ↓
Answer 2
    ↓
More conversation...


Eventually, the available context capacity can be reached. The application may need to shorten the conversation,
remove older messages, or summarize previous history to fit within the limit.

Important: A context window is not the same as long-term memory. 
Information outside the current context is not automatically available to the model.

************************ KV Cache (Key-Value Cache)  **************

What is KV Cache?
1. First, understand the problem
Suppose you ask Gemma:
"Explain how C# works."

Gemma generates its answer one token at a time:

Token 1: C#
Token 2: is
Token 3: a
Token 4: programming
Token 5: language
...

To generate each new token, the Transformer uses attention to consider relevant previous tokens.
Without a cache, the model would repeatedly calculate the attention keys and values for tokens 
it has already processed.

*****The KV Cache stores the previously calculated Key and Value vectors so the model can reuse them 
when generating the next token.

Simple example
Imagine Gemma is generating this response:
C# is a powerful programming language.
Generation step	What happens


Generate C#	Process the prompt and build initial cache entries
Generate is	Reuse cached K/V and add entries for newly processed tokens
Generate a	Reuse the cache again and extend it
Generate powerful	Continue reusing and updating the cache

The exact internal processing depends on the model and runtime, 
but the central idea is the same: reuse previous K/V calculations rather than recomputing them all.

4. Why is KV Cache important?
- Faster generation: reduces repeated attention computation.
- Better efficiency: particularly useful when generating long responses.
- Memory trade-off: cached K/V tensors consume memory, and their size generally grows as more tokens are retained.
Remember: KV Cache improves generation efficiency; 
it does not give the model permanent memory of past conversations.


**************************** Context Window vs. KV Cache******************

The main difference

Context Window
The maximum number of tokens the model can consider in its current context, 
including the input and, subject to the configured limits, generated tokens.
Think: How much information fits?




KV Cache
Stores previously calculated Key and Value tensors so the model can reuse them 
during autoregressive generation.
Think: Which calculations can be reused?

The model processes the current conversation as its context.
- The context window limits how many tokens can fit in that context.
- The KV Cache helps the model avoid recalculating previously processed tokens' 
    attention keys and values when generating the next answer.

*** What is streaming?
Streaming means displaying the model's response as it generates it, 
instead of waiting for the entire response to finish.

How does your Gemma code already support streaming?
In your existing C# console app, you used:

using var tokenizerStream = tokenizer.CreateStream();

while (!generator.IsDone())
{
    generator.GenerateNextToken();

    var outputTokens = generator.GetNextTokens();

    foreach (var token in outputTokens)
    {
        Console.Write(tokenizerStream.Decode(token));
    }
}


Let's understand each part.
Code	            Purpose
CreateStream()	    Creates a decoder that converts generated tokens into readable text incrementally.
IsDone()	        Checks whether generation has finished.
GenerateNextToken()	Advances generation by one step.
GetNextTokens()	    Retrieves the newly generated token IDs.
Decode(token)	    Converts each generated token into text.
Console.Write(...)	Displays the text immediately without automatically adding a new line.

Important: Console.Write() is what lets the text appear incrementally in the console. 
Console.WriteLine() would add a newline after each call.
