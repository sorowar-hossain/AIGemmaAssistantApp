 
 **************Transformer***************

A Transformer is a type of neural network architecture designed to understand relationships between 
words/tokens in a sequence. It is the architecture behind models 
such as Gemma, GPT, BERT, and many other modern LLMs.

In this context, “sequence” simply means an ordered list of tokens.

For example, take this sentence:

"I love C# programming"

After tokenization, it might become something like:

["I", "love", "C#", "programming"]

This is a sequence because the tokens have a specific order:

1 → I
2 → love
3 → C#
4 → programming
Why does order matter?

Compare:

"I love C#"

with:

"C# love I"

They contain similar words, but the order is different, so the meaning is different.

That's why a Transformer needs to understand the relationship between tokens within a sequence.

In ML/LLM terminology

You can think of it like this:

Sentence
   ↓
Tokenizer
   ↓
Token IDs
   ↓
[101, 2057, 2293, 1046, ...]
   ↑
   └── This ordered collection is a sequence

So when I said:

“Transformers understand relationships between words/tokens in a sequence.”

I simply meant:

Transformers understand how tokens relate to each other while considering their order in the input.

For example:

"The cat eats fish"

Sequence:
[The] → [cat] → [eats] → [fish]

And self-attention helps each token look at the other tokens in that sequence and determine which ones are important.

Next topic: Q, K, V in more detail.

You already understand the calculation, so now let's understand why we need three different vectors.

Q = Query

The Query represents:

"What information am I looking for?"

For example, when processing:

"The employee submitted the application because he was sick."

For the token "he", its Query helps determine what information it needs from the other tokens.

K = Key

The Key represents:

"What kind of information do I contain?"

Every token has a Key.

The model compares:

Query of "he"
        ↓
Keys of all tokens

If the Query and a Key match strongly, that token receives a higher attention score.

V = Value

The Value represents:

"What actual information should I provide if you pay attention to me?"

After determining which tokens are important, the model uses their Values to create the new representation.

Simple analogy

Imagine a database search:

Query
  ↓
"What am I looking for?"

Key
  ↓
"Does this record match the search?"

Value
  ↓
"Here is the actual information from the record."

So:

Q → asks
K → matches
V → provides

One sentence to remember:

Query finds what is relevant, Key determines how relevant it is, and Value provides the information.

***********Multi Head attention*********
What is Multi-Head Attention?

Instead of doing one attention operation, the Transformer does several attention operations in parallel.

These are called heads.

            Input
              ↓
 ┌──────────┬──────────┬──────────┐
 ↓          ↓          ↓
Head 1     Head 2     Head 3
 ↓          ↓          ↓
Attention  Attention  Attention
 └──────────┼──────────┘
            ↓
        Concatenate
            ↓
      Final projection

So:

Multi-Head Attention = multiple attention heads working on the same input, 
each learning different relationships.

2. Why do we need multiple heads?

Consider:

"The employee submitted the leave application because he was sick."

Different relationships may be useful.

One attention head might learn:

"he" → "employee"

Another might focus on:

"submitted" → "application"

Another might focus on:

"leave" → "application"

So different heads can learn different types of relationships.

You can think of them as different "ways of looking at" the same sentence.


With multiple heads:
                 ┌→ Attention Head 1 ─┐
Input ───────────┼→ Attention Head 2 ─┼→ Concatenate → Output
                 ├→ Attention Head 3 ─┤
                 └→ Attention Head 4 ─┘

 Attention and FFN have different jobs:

| Component            | Main job                                   |
| -------------------- | ------------------------------------------ |
| Self-Attention       | Exchange information between tokens        |
| Feed-Forward Network | Process/transform each token's information |
| LayerNorm            | Keep representations stable                |
| Residual/Add         | Preserve and reuse previous information  
                       |"Keep the original information, then add what the attention layer learned."
| Positional Encoding  | Provide token-position information         |


If these four ideas are clear, you've understood the core of a Transformer encoder layer.

What is ONNX Runtime?

ONNX Runtime (ORT) is a machine-learning inference engine.

In simple terms:

ONNX Runtime runs a trained AI model and gives you its output.

It does not train the model. It executes the already-trained model.
